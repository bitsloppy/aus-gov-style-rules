# AGSM Structuring Content — System Prompt Drop-in

> Compiled from stylemanual.gov.au · 2026-09-22

---

## Headings

- **Sentence case** only — first word + proper nouns + acronyms. Not Title Case. Not ALL CAPS.
- No full stop at the end of any heading.
- Maximum **70 characters** including spaces.
- **Keywords first** — the most meaningful word(s) must appear in the first 2–3 words. Avoid filler openers: *Find out about*, *Information about*, *Learn how to*.
- **Descriptive, not vague**: *Apply for a disability support pension* — not *More information* or *Overview*.
- Do not phrase headings as questions (*What do I need?*) — state the topic directly.
- Follow a **sequential hierarchy**: H1 → H2 → H3 → H4. Never skip a level.
- Only **one H1** per page.
- At least one sentence of body text between consecutive headings.
- All headings at the same level must use **parallel grammatical structure** (all imperative verbs, or all noun phrases).

## Lists

- Minimum **two items** in any list.
- **Parallel structure**: every item begins with the same word type, uses the same tense, follows the same pattern.
- Lead-in phrase ends with a **colon**.
- **No semicolons or commas** at the end of list items.
- No *and* or *or* between items.
- No trailing *etc.*
- Fragment list items: **lowercase** start (unless proper noun or acronym); **full stop on the final item only**.
- **Numbered lists only** when sequence matters — use bullets when order is arbitrary.
- Second-level list items: **en dash** (–) as the marker, not hollow bullets or hyphens.

## Paragraphs

- **One topic per paragraph**.
- Open with a **topic or transition sentence**.
- Web/mobile: **2–3 sentences** per paragraph; long-form documents: maximum **6 sentences**.
- Maximum **25 words** per sentence.
- Pronouns starting a paragraph (*this*, *these*, *they*) must have an unambiguous referent in the preceding text.

## Tables

- Use tables only when content is too complex for prose or a list, and when users need to compare values or find exact figures.
- Every table needs a **descriptive caption** and proper **row and column headings**.
- Every table must be **cross-referenced in body text** by number or title — not *the table below* or *the table above*.
- No empty cells — use **nil**, **n/a**, or **0** where data is absent.
- No colour as the sole means of conveying meaning.
- No nested tables.
- Complex tables (irregular headers, merged cells): include a structural **summary** describing what rows and columns represent.

## Links

- Link text must describe the destination when **read in isolation** — not *click here*, *here*, *read more*, or *more information*.
- **Keywords first** in link text.
- Links to downloadable files: include file type and size — `Annual Report 2023–24 [PDF 2.1 MB]`.
- Mailto links: the visible text must be the **email address itself**.
- Deep-link to the **specific page** the user needs — not to a homepage.
- Link to existing content rather than duplicating it.

## Text boxes and callouts

- Use for **supplementary** content only — summaries, examples, checklists, definitions.
- Critical information that must be read in sequence belongs in body text, not a callout.
- Use sparingly — overuse reduces impact.
- HTML: use `<aside>` or `role="complementary"` — not a plain `<div>`.
- Microsoft Word/PowerPoint: do not use floating Insert > Text Box — use a bordered paragraph style or a one-by-one table instead.
